# 恐惧悬疑模型数据集与微调流水线

本文是 `training/` 下数据规划、教师数据生产、盲测和 QLoRA 微调的唯一权威操作文档。所有命令
均从 `scoring-for-TTS` 仓库根目录执行。不要再使用旧命令中的 `--source-limit`、`--train-count`、
`--blind-count`、`--validation-count` 或 `--test-count`；数据范围和集合分配已改由 Step 0 冻结清单
统一控制。

## 目标与职责边界

第一阶段只训练一个能力：

```text
audio-polisher-lora
完整文学稿 A → 保真且适合有声演播的纯文本 B
```

不要把故事创作、导演 JSON、speaker/emotion、SFX、BGM、SSML、`control_instruction` 或 TTS 指令
混入这批监督微调数据。`TTS-Studio-WebUI` 继续负责把 B 转成角色、旁白、表演和音效等导演层结构。

| 阶段 | 默认配置 | 职责 |
| --- | --- | --- |
| Step 0 | Python | 冻结来源、哈希和 train/validation/blind/test 分配 |
| Step 1 | Luna medium；疑难可用 Sol high | 识别整期杂志中的完整故事边界、清洗、去重 |
| Step 2 | Luna high | 二次边界审计、人物、事实、线索、反转和 OCR 风险 |
| Step 3 | Terra high；困难样本 xhigh | 生成 A→B 教师答案 |
| Step 4 | 独立 Terra high | 对照 A/B 复核保真度和有声适配 |
| Step 5 | Sol high；金标准 xhigh | 只裁决疑难、validation 和显式金标准 |
| Step 6 | Python + 必要人审 | 质量门禁并导出 ShareGPT 数据 |
| Step 7 | 本地 Qwen 与多个教师配置 | 匿名文本盲测和音频盲听 |
| Step 8 | LLaMA-Factory | Qwen3.5-9B 4-bit QLoRA 微调 |

## 已冻结的数据规划

原始 Markdown 只保存在 `training/原始资源/`，不复制到物理的训练集、验证集或测试集目录。当前
恐惧悬疑数据集只使用以下四个刊物：

- `怖客`
- `猛鬼杂志故事`
- `男生女生金版`
- `悚族`

`岁月推理` 和 `啄木鸟` 属于推理方向，不进入本版本。当前四个目标目录共有 542 份候选来源。
Step 0 从每个刊物稳定选取 20 份，共冻结 80 份：

| 集合 | 每刊物来源数 | 总来源数 | 用途 |
| --- | ---: | ---: | --- |
| `train` | 14 | 56 | LoRA 参数训练 |
| `validation` | 2 | 8 | 选择 checkpoint、学习率和训练轮次 |
| `blind` | 2 | 8 | Step 7 匿名比较，不参与训练 |
| `test` | 2 | 8 | 最终版本一次性验收 |

这相当于来源级 70%/10%/10%/10%。原计划的 70%/15%/15% 缺少独立盲测集；一旦用测试集反复
选择模型，它就不再是未见测试集。当前划分因此把后 30% 拆成三个职责明确的集合。

选择不是“按文件名取前 20 个”。脚本使用固定种子、稳定哈希、年份分层和期号/副刊分组，优先
覆盖不同年份并避免同一期不同版本跨集合。集合按来源文件冻结；一个来源中识别出的所有故事都继承
同一 split。不同来源最后得到的故事数可能不同，这是整期防泄漏的必要结果。

冻结结果位于 `training/数据集规划/fear-suspense-v1/`：

```text
plan.json                 # 参数、统计和清单哈希
source_inventory.jsonl    # 542 份候选来源及哈希
selected_sources.jsonl    # Step 1 唯一允许处理的 80 份来源
train.txt
validation.txt
blind.txt
test.txt
```

当前计划哈希为
`7730db559b2465d2f137be5c007c6588f18b3a9e57a9f6be51c62788e79fe6e2`。验证当前原始资源仍能生成
同一方案：

```bash
python training/script/step_0_plan_sources.py --dry-run
```

预期看到 542 份候选、80 份入选，以及 train 56、validation 8、blind 8、test 8。dry-run 不写文件。
如果来源内容、目录或规划参数有意变化，不要覆盖已使用的 v1；应改用新的 `--dataset-version`、
`--plan-dir` 和 `--work-dir` 生成 v2。否则 Step 1 会因哈希漂移而停线。

## Step 0：检查冻结方案

仓库已经生成 v1 计划，正常操作只需执行检查：

```bash
python training/script/step_0_plan_sources.py --dry-run
```

`selected_sources.jsonl` 同时记录相对路径、刊物、来源组、年份、split、SHA-256、字节数、行数和
标题数。Step 1 会逐项复算，任何内容漂移或来源组跨集合都会直接报错。

## Step 1：边界识别、清洗和去重

### Step 1a：本地检查

```bash
python training/script/step_1_prepare_stories.py --auto-boundaries --dry-run
```

本步骤应显示“冻结来源：80”和“AI 边界识别待处理：80 / 来源文件：80”，然后打印
`Step 1a 检查通过`。命令预览末尾的“后续参数已省略”只是截断展示，不是报错。dry-run 不调用模型，
也不写流水线文件。

### Step 1b：四刊物代表性试跑

确认对这些文本拥有相应的云端处理和训练授权后执行：

```bash
python training/script/step_1_prepare_stories.py --auto-boundaries \
  --work-dir work/training-pipeline-fear-v1-pilot \
  --pilot-per-collection 1 \
  --rights-status approved_for_cloud_training \
  --resolve-ambiguous --continue-on-error
```

该命令从每个目标刊物选择 1 份 train 来源，共调用 4 份，而不是取全局排序第一份。检查
`automatic_boundary_report.json`、`boundary_review_queue.jsonl` 和提取出的 `stories/`；试跑目录不用于
后续正式训练。

### Step 1c：正式处理 80 份冻结来源

```bash
python training/script/step_1_prepare_stories.py --auto-boundaries \
  --rights-status approved_for_cloud_training \
  --resolve-ambiguous \
  --boundary-workers 3 --boundary-review-workers 2 \
  --continue-on-error
```

Python 先生成带行号的标题和段落证据；Luna 首轮识别完整小说，Sol 只复核低置信度或真正边界
歧义。非小说、连载和长度不合格项由确定性规则排除。默认置信度低于 0.80 的记录进入复核或人工队列，
不会进入后续训练。

出现 429、额度或连接限制时，把两个 worker 参数降为 1。需要诊断证据不足时才使用
`--boundary-full-source`，因为它会让首轮模型读取整份原文并显著增加时间。

按一次 Ctrl+C 后，脚本会取消未提交任务、终止当前 Codex 子进程并简洁退出。中断、网络失败或
部分来源失败后，重复同一条 Step 1c 命令即可；来源哈希匹配的有效结果会复用。不要为普通续跑添加
`--refresh-boundaries` 或 `--overwrite`。

## Step 2：理解故事并二次审计边界

先检查，再分批实跑：

```bash
python training/script/step_2_analyze_stories.py \
  --limit 100 --workers 4 --continue-on-error --dry-run
python training/script/step_2_analyze_stories.py \
  --limit 100 --workers 4 --continue-on-error
```

默认只处理 train 和 validation，不会提前碰 blind/test。`--limit 100` 限制本次尚未完成项；重复
实跑命令直到“待处理：0”。不要在断点续跑时加 `--overwrite`。

若生成 `boundary_repair_queue.jsonl`，先抽查建议，再应用可信修复并重跑 Step 2：

```bash
python training/script/step_1_prepare_stories.py --apply-boundary-repairs --overwrite
python training/script/step_2_analyze_stories.py \
  --limit 100 --workers 4 --continue-on-error
```

## Step 3：生成教师答案 B

```bash
python training/script/step_3_rewrite_stories.py \
  --variant teacher --limit 100 --workers 3 --continue-on-error --dry-run
python training/script/step_3_rewrite_stories.py \
  --variant teacher --limit 100 --workers 3 --continue-on-error
```

普通故事使用 Terra high，困难故事使用 Terra xhigh。默认只处理 train/validation。任何新增人物、
事实改写、Markdown、speaker/emotion、SFX、BGM 或导演/TTS 标签都会被确定性门禁标记或拒绝。

## Step 4：独立复核 A/B

```bash
python training/script/step_4_review_rewrites.py \
  --variant teacher --limit 100 --workers 4 --continue-on-error --dry-run
python training/script/step_4_review_rewrites.py \
  --variant teacher --limit 100 --workers 4 --continue-on-error
```

门禁要求事实保真不低于 0.95、有声可读性不低于 0.85、悬念保留不低于 0.85，且没有
major/critical 问题。模型返回的 `pass` 不能覆盖确定性检查。

## Step 5：只裁决疑难和 validation

```bash
python training/script/step_5_adjudicate_stories.py \
  --variant teacher --limit 100 --workers 2 --continue-on-error --dry-run
python training/script/step_5_adjudicate_stories.py \
  --variant teacher --limit 100 --workers 2 --continue-on-error
```

困难故事、Terra 门禁未通过的故事、validation 和显式 `--gold-manifest` 才进入 Sol。日常流程禁止
使用 `--include-split test`；test 只在模型、Prompt、超参数和 checkpoint 全部冻结后使用一次。

## Step 6：审核和导出训练数据

先生成 Easy Dataset 审核候选：

```bash
python training/script/step_6_export_datasets.py --variant teacher
```

候选文件位于
`work/training-pipeline-fear-v1/exports/easy_dataset_candidates.jsonl`。可把 instruction/input/output
导入本地 Easy Dataset。高置信 train 可由双重 AI 与确定性门禁自动批准；validation 仍须人工批准：

```bash
python training/script/step_6_export_datasets.py \
  --variant teacher --auto-approve-passed --overwrite
```

人工清单每条批准记录必须绑定候选输出哈希和审核人：

```json
{"source_id":"story_0123456789abcdef","decision":"approved","reviewer":"审核人","split":"validation","output_sha256":"64位SHA-256"}
```

合并人工批准项：

```bash
python training/script/step_6_export_datasets.py \
  --variant teacher --auto-approve-passed \
  --approval-manifest work/training-pipeline-fear-v1/approvals.jsonl \
  --overwrite
```

最终输出包含 ShareGPT JSON/JSONL、`dataset_info.json`、导出报告和拒绝清单。blind/test 永远不会进入
训练或 validation 导出。

## Step 7：blind 匿名文本和音频比较

blind 在日常 Step 2–6 中保持未使用。进入方案比较阶段后，先只为 blind 生成分析：

```bash
python training/script/step_2_analyze_stories.py \
  --include-split blind --limit 100 --workers 4 --continue-on-error
```

然后生成五个候选变体：

```bash
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant local_qwen --model qwen3.5:9b --local-provider ollama \
  --normal-reasoning-effort medium --hard-reasoning-effort medium
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant luna_high --model gpt-5.6-luna \
  --normal-reasoning-effort high --hard-reasoning-effort high
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant luna_xhigh --model gpt-5.6-luna \
  --normal-reasoning-effort xhigh --hard-reasoning-effort xhigh
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant terra_high --model gpt-5.6-terra \
  --normal-reasoning-effort high --hard-reasoning-effort high
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant terra_xhigh --model gpt-5.6-terra \
  --normal-reasoning-effort xhigh --hard-reasoning-effort xhigh
python training/script/step_7_prepare_blind_test.py
```

Step 7 默认使用当前全部 blind 故事，不再硬编码要求 60 篇；如果将来数据充足且要固定 60 篇，可显式
传 `--count 60`。默认从中冻结最多 10 篇音频子集。评价权重为事实保真 35%、悬疑恐惧氛围 25%、
有声朗读适配 20%、人物对白清晰 10%、导演层兼容性 10%。所有候选匿名打乱后再评分。

## Step 8：生成并执行 QLoRA 配置

```bash
python training/script/step_8_prepare_llamafactory.py --dry-run
python training/script/step_8_prepare_llamafactory.py
cd ~/github/LlamaFactory
llamafactory-cli train \
  ~/github/scoring-for-TTS/work/training-pipeline-fear-v1/llamafactory/audio_polisher_lora_sft.yaml
```

配置使用 `Qwen/Qwen3.5-9B`、`qwen3_5_nothink`、4-bit bitsandbytes QLoRA、LoRA rank 16、梯度
检查点和 batch size 1。`cutoff_len=8192` 只是单张 16 GB GPU 的起步值；先用小样本实测显存。
Step 6 默认拒绝估算超过 7500 Token 的样本，不能依赖训练框架静默截断故事结尾。

## 停线条件与人工职责

- 未明确拥有云端处理和训练授权时，不得使用 `approved_for_cloud_training`。
- 冻结来源的路径、内容哈希、行数或标题数变化时，停止并规划新数据集版本。
- 边界未通过 Step 1 和 Step 2、故事不完整、OCR 串页、缺结局或发生近重复时，不进入改写。
- B 出现剧情硬错误、新人物、导演/TTS 标签或上下文截断风险时，不进入最终数据。
- validation 必须人工批准；blind 用于模型选择；test 在所有选择完成后才做一次最终验收。
- 最终文本盲测和音频盲听仍需人工完成，不能由教师模型代替。

## 常见问题

`Step 1a 检查通过` 表示命令工作正常，并不表示已经调用模型。下一步是 Step 1b 四刊物试跑。

如果命令提示 `unrecognized arguments: --source-limit ...`，说明使用了废弃文档或历史命令。请直接
复制本文快速操作表中的新命令；来源数和 split 已由 Step 0 清单冻结。

如果 Step 1 提示来源哈希变化，不要用 `--overwrite` 绕过。先确认文件是否被意外修改；若是有意更新，
创建 v2 计划和全新的 v2 工作目录。

如果模型任务长时间没有完成，心跳只是说明任务仍在运行。可按一次 Ctrl+C 安全退出，再把 worker
降为 1 后重复同一命令续跑。
