第一阶段只训练一个能力：


不要把故事创作、导演 JSON、speaker/emotion、SFX、BGM、SSML、`control_instruction` 或 TTS 指令
混入这批监督微调数据。`TTS-Studio-WebUI` 继续负责把 B 转成角色、旁白、表演和音效等导演层结构。

### 断点续跑与额度耗尽

Step 1–5 的每个模型结果都先通过结构、来源 ID/路径和输入哈希校验，再原子写入独立 JSON。重复执行
完全相同的命令时，脚本会先校验这些结果并跳过有效项，只把缺失、损坏或输入哈希过期的项加入本轮
队列。普通续跑不要添加 `--overwrite`、`--refresh-boundaries`，也不要更换 `--work-dir`。

进度账本位于 `work/training-pipeline-fear-v1/progress/`。其中 Step 1 分为首轮识别和 Terra 复核两份，
Step 2–5 按阶段、variant 和 split 范围分开；Step 6–8 完成写入后也会留下记录。重点字段是：

- `status`：`running`、`partial`、`completed`、`interrupted`、`quota_exhausted` 或 `failed`；
- `completed_items` / `pending_items`：全部有效断点和仍需处理的数量；
- `skipped_existing_items`：本次启动时因已有有效结果而跳过的数量；
- `completed_this_run` / `failed_this_run`：仅本次运行的增量。

Codex 明确返回 usage limit、额度耗尽或 `quota_exceeded` 时，该信号优先于
`--continue-on-error`：脚本不再重试触发项，立即停止提交后续队列，并终止仍在运行的同阶段模型
进程。已原子写入的结果保持有效。额度恢复后重复原命令即可续跑。`--retries` 只重试临时网络、
传输或超时错误，默认最多额外一次；结构校验失败不会重复运行相同提示。

### 模型和速度硬约束

Step 1–5 的自动云端调用只允许显式的 `gpt-5.6-luna` 与 `gpt-5.6-terra`。脚本拒绝
`gpt-5.6-sol`、会隐式路由到 Sol 的 `gpt-5.6` 别名，以及 `xhigh`、`max`、pro。所有命令均忽略
用户 Codex 配置并固定 Standard，不提供 `--profile`，所以 Fast 模式不能通过脚本或本地 profile
进入流水线。

Terra medium 与唯一一次 Terra high 修复仍不能通过时，脚本不会调用 Sol，而是在
`manual_escalation/` 写出提示词和目标结果路径。用户手工处理后把纯 JSON 保存到提示的
`manual_results/` 路径，再重复原命令即可校验和导入。

### Step 1c：正式处理 80 份冻结来源


Python 先生成带行号的标题和段落证据；Luna medium 首轮识别完整小说。Terra medium 只复核低置信度
或完整性不确定的故事，并且只读取首轮 JSON、紧凑标题清单和风险故事起止两侧各约 30 行局部原文，

Sol 或已导入的人工结果只要来源哈希匹配都会跳过。不要为了加快进度把 `--boundary-review-limit`

结束，应转 Step 1d；继续重复 Step 1c 只会打印同一批等待项，并以非零退出码表示 Step 1 尚未完成。

出现临时 429 或连接不稳定时，可把两个 worker 参数降为 1。明确额度耗尽时脚本会自动停线；等待
额度恢复后重复原命令。需要诊断首轮证据不足时才使用 `--boundary-full-source`，因为它会让 Luna
读取整份原文并显著增加时间；Terra 复核始终使用局部包。

按一次 Ctrl+C 后，脚本会取消未提交任务、终止当前 Codex 子进程并简洁退出。中断、网络失败或
部分来源失败后，重复同一条 Step 1c 命令即可；来源哈希匹配的有效结果会复用。不要为普通续跑添加

### Step 1d：人工 Sol 处理未决边界

这一阶段由用户手工完成，脚本不会调用 Sol。先运行 Step 1a dry-run 确认“自动待处理 0”，再列出尚未
保存人工结果的升级包：

```bash
python - <<'PY'
from pathlib import Path

packages = Path("work/training-pipeline-fear-v1/manual_escalation/step_1")
results = Path("work/training-pipeline-fear-v1/manual_results/step_1_boundary_review")
pending = [
    package
    for package in sorted(packages.glob("source_*.md"))
    if not (results / f"{package.stem}.json").is_file()
]
print(f"等待人工 Sol：{len(pending)}")
for package in pending:
    print(f"{package} -> {results / (package.stem + '.json')}")
PY
```

当前应列出 17 项。每一项都按下面的方式单独处理，避免不同来源相互污染：

1. 从仓库根目录新建一个人工 Codex 任务，明确选择 `gpt-5.6-sol`、Standard、medium；不要选择 Fast。
2. 打开一个 `manual_escalation/step_1/source_*.md`，只复制“可复制提示词”代码块交给 Sol。提示词只允许

3. 要求最终只返回符合 `training/script/schemas/story_boundaries.schema.json` 的 JSON 对象，不要返回

4. 把纯 JSON 保存到升级包顶部指定的
   `manual_results/step_1_boundary_review/source_*.json` 精确路径。文件名必须与升级包同 stem。
5. Sol medium 的结果若未通过本地结构或绑定校验，优先在同一个人工会话中只修正报错字段；确有语义

## Step 6：审核和导出训练数据

先生成 Easy Dataset 审核候选：

```bash
python training/script/step_6_export_datasets.py --variant teacher
```

候选文件位于
`work/training-pipeline-fear-v1/exports/easy_dataset_candidates.jsonl`。可把 instruction/input/output
导入本地 Easy Dataset。高置信 train 可由双重 AI 与确定性门禁自动批准；validation 仍须人工批准：

```bash
python training/script/step_6_export_datasets.py \
  --variant teacher --auto-approve-passed --overwrite
```

人工清单每条批准记录必须绑定候选输出哈希和审核人：

```json
{"source_id":"story_0123456789abcdef","decision":"approved","reviewer":"审核人","split":"validation","output_sha256":"64位SHA-256"}
```

合并人工批准项：

```bash
python training/script/step_6_export_datasets.py \
  --variant teacher --auto-approve-passed \
  --approval-manifest work/training-pipeline-fear-v1/approvals.jsonl \
  --overwrite
```

最终输出包含 ShareGPT JSON/JSONL、`dataset_info.json`、导出报告和拒绝清单。blind/test 永远不会进入
训练或 validation 导出。

## Step 7：blind 匿名文本和音频比较

blind 在日常 Step 2–6 中保持未使用。进入方案比较阶段后，先只为 blind 生成分析：

```bash
python training/script/step_2_analyze_stories.py \
  --include-split blind --limit 10 --workers 2 --continue-on-error
```

先只生成同一批 10 篇的三个候选变体：

```bash
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant local_qwen --model qwen3.5:9b --local-provider ollama \
  --normal-reasoning-effort medium --hard-reasoning-effort medium --limit 10
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant luna_medium --model gpt-5.6-luna \
  --normal-reasoning-effort medium --hard-reasoning-effort medium --limit 10
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant terra_medium --model gpt-5.6-terra \
  --normal-reasoning-effort medium --hard-reasoning-effort medium --limit 10
python training/script/step_7_prepare_blind_test.py
```

Step 2、Step 3 与 Step 7 都按 source_id 稳定选择同一批；Step 7 默认最多使用 10 篇 blind 故事，
先根据结果决定是否值得显式扩大 `--count` 和上游 `--limit`。默认音频子集也是最多 10 篇。评价权重为
事实保真 35%、悬疑恐惧氛围 25%、
有声朗读适配 20%、人物对白清晰 10%、导演层兼容性 10%。所有候选匿名打乱后再评分。

## 停线条件与人工职责

- 未明确拥有云端处理和训练授权时，不得使用 `approved_for_cloud_training`。
- 冻结来源的路径、内容哈希、行数或标题数变化时，停止并规划新数据集版本。
- 边界未通过 Step 1 和 Step 2、故事不完整、OCR 串页、缺结局或发生近重复时，不进入改写。
- B 出现剧情硬错误、新人物、导演/TTS 标签或上下文截断风险时，不进入最终数据。
- validation 必须人工批准；blind 用于模型选择；test 在所有选择完成后才做一次最终验收。
- 最终文本盲测和音频盲听仍需人工完成，不能由教师模型代替。

## 常见问题

`Step 1a 检查通过` 表示命令工作正常，并不表示已经调用模型。下一步是 Step 1b 四刊物试跑。

如果命令提示 `unrecognized arguments: --source-limit ...`，说明使用了废弃文档或历史命令。请直接
复制本文快速操作表中的新命令；来源数和 split 已由 Step 0 清单冻结。

如果 Step 1 提示来源哈希变化，不要用 `--overwrite` 绕过。先确认文件是否被意外修改；若是有意更新，
创建 v2 计划和全新的 v2 工作目录。

如果模型任务长时间没有完成，心跳只是说明任务仍在运行。可按一次 Ctrl+C 安全退出，再把 worker
降为 1 后重复同一命令续跑。

如果提示额度耗尽，不要让脚本继续遍历剩余队列，也不要删除 `boundary_detection/`、
`boundary_detection_review/`、`analysis/`、`rewrites/`、`reviews/` 或 `adjudications/`。新版本会自动
停线，并在 `progress/` 中记录 `quota_exhausted`；恢复额度后复制原命令重新执行。
