# 最适合你的模型流水线

本文提炼自[共享讨论](https://chatgpt.com/share/6a9150cd-c0bc-83ec-a454-a8b91dcf14d9)，并按
本机最新的 `~/github/easy-dataset`、`~/github/LlamaFactory`、
`~/github/TTS-Studio-WebUI` 和 `~/github/TTS-and-VoiceDesign` 实际接口落地。

## 结论

第一阶段只训练一个能力：

```text
audio-polisher-lora
完整文学稿 A → 保真且适合有声演播的纯文本 B
```

不要把故事创作、导演 JSON、speaker/emotion、SFX、BGM、`control_instruction` 或 TTS 指令混入
这批监督微调数据。模型分工固定为：

| 阶段 | 默认配置 | 职责 |
| --- | --- | --- |
| 确定性处理 | Python，不用大模型 | 清洗、人工边界落盘、去重、字数、版权门禁、Schema 和禁用标签检查 |
| 故事理解 | GPT-5.6 Luna High Standard | 人物、不可变事实、线索、误导、反转、故事 DNA、OCR 风险和难度 |
| A→B 教师答案 | GPT-5.6 Terra High Standard | 事实保真的有声化改写 |
| 困难改写 | GPT-5.6 Terra xhigh Standard | 多人对白、双时间线、身份隐藏、密集伏笔等复杂故事 |
| 独立复核 | 第二次 Terra High Standard | 只比较 A/B，不重新创作 |
| 疑难裁决 | GPT-5.6 Sol High/xhigh Standard | 冲突样本、困难样本、验证/测试金标准 |
| 部署模型 | 本地 Qwen3.5-9B + LoRA | TTS 前置文本加工；同时保留未微调模型作为基线 |

Fast 不作为默认配置。额度应优先用于独立候选、独立复核和 Sol 疑难裁决。OpenAI 当前官方模型
定位、推理强度和命名见[GPT-5.6 模型指南](https://developers.openai.com/api/docs/guides/latest-model)；
脚本使用的 `codex exec --ephemeral`、只读沙箱、`--output-schema` 与 `-o` 均来自
[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。Codex 默认复用本机已保存的
登录状态，认证边界见[官方认证说明](https://learn.chatgpt.com/docs/auth)。

## 数据和运行目录

仓库只保存文档、脚本、Schema 和测试。所有中间数据默认写入已忽略的：

```text
work/training-pipeline/
├── source_inventory.jsonl
├── boundary_template.jsonl
├── stories.jsonl
├── stories/
├── analysis/
├── rewrites/<variant>/
├── reviews/<variant>/
├── adjudications/<variant>/
├── exports/
├── blind_test/
└── llamafactory/
```

现有 645 份 Markdown 多数是整期杂志，不等于完整故事。禁止按固定字数随机切片，也禁止把一整期
杂志当一篇故事发送给模型。Step 1 只把 Markdown 标题列为候选；故事起止行必须人工确认。

## 执行顺序

### Step 1：清洗、完整故事边界、版权和去重

先生成来源与标题候选：

```bash
python training/script/step_1_prepare_stories.py --dry-run
python training/script/step_1_prepare_stories.py
```

复制 `work/training-pipeline/boundary_template.jsonl` 为单独的审核清单，逐篇填写真实的完整故事边界。
只有确实具备云端处理、训练及计划用途授权的记录才能写：

```json
{"source_path":"岁月推理/某期.md","title":"故事名","start_line":120,"end_line":860,"boundary_status":"approved","rights_status":"approved_for_cloud_training","split":"auto"}
```

`start_line`、`end_line` 都是 1 起始且包含端点。未确认边界使用 `needs_review`；权利不明确使用
`unknown`，后续云端脚本会强制跳过。确认后执行：

```bash
python training/script/step_1_prepare_stories.py \
  --boundary-manifest work/training-pipeline/boundaries.reviewed.jsonl \
  --dry-run
python training/script/step_1_prepare_stories.py \
  --boundary-manifest work/training-pipeline/boundaries.reviewed.jsonl \
  --overwrite
```

默认按内容哈希确定性冻结 60 篇 `blind`、20 篇 `validation`，其余为 `train`。精确重复和
SimHash 近重复只标记、不删除来源证据。

### Step 2：Luna 理解完整故事

```bash
python training/script/step_2_analyze_stories.py --dry-run
python training/script/step_2_analyze_stories.py
```

每篇故事是一次独立、临时、只读 Codex 会话。输出包含人物、不可变事实、线索、误导、反转、
故事 DNA、OCR 风险和 `normal/hard` 难度，并在落盘前再次校验。

### Step 3：Terra 生成核心 B

```bash
python training/script/step_3_rewrite_stories.py --variant teacher --dry-run
python training/script/step_3_rewrite_stories.py --variant teacher
```

普通样本自动使用 Terra High，`difficulty=hard` 自动使用 Terra xhigh。输出中的 Markdown、
speaker/emotion、SFX、BGM、`control_instruction` 和非语言标签会被确定性拒绝；脚本还会标记 B 中
新增但 A 中未出现的人名候选。

### Step 4：第二次 Terra 独立复核

```bash
python training/script/step_4_review_rewrites.py --variant teacher --dry-run
python training/script/step_4_review_rewrites.py --variant teacher
```

门禁要求事实保真不低于 0.95、有声可读性不低于 0.85、悬念保留不低于 0.85，且没有
major/critical 问题。模型的 `pass` 不能覆盖确定性门禁。

### Step 5：Sol 只裁决疑难和金标准

```bash
python training/script/step_5_adjudicate_stories.py --variant teacher --dry-run
python training/script/step_5_adjudicate_stories.py --variant teacher
```

困难故事、Terra 门禁未通过的故事、`validation/test` 和显式 `--gold-manifest` 才进入 Sol。
普通疑难样本使用 High，金标准使用 xhigh；默认仍是 Standard，不开启 Fast。

### Step 6：Easy Dataset 人审和 ShareGPT 导出

先生成审核候选：

```bash
python training/script/step_6_export_datasets.py --variant teacher
```

把 `work/training-pipeline/exports/easy_dataset_candidates.jsonl` 导入本地 Easy Dataset，映射
`instruction`、`input`、`output`，完成盲审、打分和筛选。不要把 Codex `--json` 事件流当训练数据。

从 Easy Dataset 整理一份审核清单；批准项必须有审核人：

```json
{"source_id":"story_0123456789abcdef","decision":"approved","reviewer":"审核人","split":"train","output_sha256":"候选文件中的64位output_sha256"}
```

然后生成最终数据：

```bash
python training/script/step_6_export_datasets.py \
  --variant teacher \
  --approval-manifest work/training-pipeline/approvals.jsonl \
  --overwrite
```

输出同时包含与本地 Easy Dataset/LLaMA-Factory 一致的 `messages/role/content` ShareGPT JSON、
JSONL 和 `dataset_info.json`。`blind/test` 不会进入 Easy Dataset 审核候选、训练或验证导出；
未经人工批准、模型门禁未通过或估算超出上下文预算的样本也不会进入最终数据。

### Step 7：60 篇文本盲测和 10 篇音频盲听

先只对冻结 `blind` 集生成五个变体。Step 3 可复用为不同教师配置；本地 Qwen 通过 Codex CLI 的
Ollama 本地 provider 运行：

```bash
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant local_qwen --model qwen3.5:9b --local-provider ollama \
  --normal-reasoning-effort medium --hard-reasoning-effort medium
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant luna_high --model gpt-5.6-luna \
  --normal-reasoning-effort high --hard-reasoning-effort high
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant luna_xhigh --model gpt-5.6-luna \
  --normal-reasoning-effort xhigh --hard-reasoning-effort xhigh
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant terra_high --model gpt-5.6-terra \
  --normal-reasoning-effort high --hard-reasoning-effort high
python training/script/step_3_rewrite_stories.py --include-split blind \
  --variant terra_xhigh --model gpt-5.6-terra \
  --normal-reasoning-effort xhigh --hard-reasoning-effort xhigh
python training/script/step_7_prepare_blind_test.py
```

每个匿名故事包同时包含 `source_a.txt` 和打乱顺序的候选 B。盲测权重固定为事实保真 35%、
悬疑恐惧氛围 25%、有声朗读适配 20%、人物对白清晰 10%、
现有导演层兼容性 10%。脚本匿名打乱模型名，并冻结 10 篇音频子集。音频子集分别导入当前
`~/github/TTS-Studio-WebUI` 脚本制作页，使用相同导演 Prompt、参考音色和
`~/github/TTS-and-VoiceDesign` 的 VoxCPM2 `POST /v1/voxcpm2/clone`（8322）生成，避免模型、
导演参数或音色成为混杂变量。

### Step 8：LLaMA-Factory 微调 Qwen3.5-9B

```bash
python training/script/step_8_prepare_llamafactory.py --dry-run
python training/script/step_8_prepare_llamafactory.py
cd ~/github/LlamaFactory
llamafactory-cli train \
  ~/github/scoring-for-TTS/work/training-pipeline/llamafactory/audio_polisher_lora_sft.yaml
```

生成配置使用本地源码已经支持的 `Qwen/Qwen3.5-9B`、`qwen3_5_nothink`、4-bit bitsandbytes
QLoRA、LoRA rank 16、梯度检查点和 batch size 1。`cutoff_len=8192` 是单张 16 GB GPU 的起步
值，不是保证值；先用小样本实测显存。Step 6 默认拒绝估算超过 7500 Token 的样本，不能依赖
LLaMA-Factory 静默截断故事结尾。

## 验收和停线条件

- 任何来源在 `rights_status` 不是 `approved_for_cloud_training` 时，停止在本地 Step 1。
- 边界未人工确认、故事不完整、OCR 串页或缺结局时，不进入教师流水线。
- B 中出现剧情硬错误、新人物、导演/TTS 标签或训练上下文截断风险时，不进入最终数据。
- 训练前必须完成 60 篇独立文本盲测；其中 10 篇还要经过现有导演层和 VoxCPM2 音频盲听。
- 第一阶段结果只用于文本润色，后续仍由现有导演层生成 Unitale 工程字段，再交给
  VoxCPM2、SFX、BGM 和 Steam Audio。
- 系统性使用 Codex 输出训练第三方模型前，应再次核对账户适用的 OpenAI 条款；期刊/小说内容
  的云端处理权、训练权和商业使用权必须分别有可审计依据。
